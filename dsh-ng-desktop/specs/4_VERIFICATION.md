# 交付与验收规范

只有满足对应验收项，`3_TASKS.md` 中的任务才允许标记完成。

## 1. 工程基线

- **V1.1**：普通 `dotnet build` 成功，启动骨架不执行旧托盘、旧安装、更新或 WebView 实验逻辑。
- **V1.2**：生产代码中不存在 Win32 托盘实现、`npm install @deepseek-ai/dsh`、更新检测、自定义标题栏和 WebView 导航白名单。
- **V1.3**：Windows 与 macOS 平台能力通过窄接口隔离，共享状态机不散布平台判断。
- **V1.4 AOT 静态门禁**：AOT、Trim 和 Single-file 分析器持续启用，生产项目不存在未处理的相关警告。
- **V1.5 AOT 编码约束**：生产代码不使用运行时程序集加载、`Reflection.Emit`、动态代理、反射扫描式注册或运行时代码编译；JSON 和平台调用采用规定的 Source Generator。

## 2. 安装事务

- **V2.1 环境缺失**：Node 或 npx 缺失、不兼容时，安装器显示明确原因和修复指引，退出为安装失败。
- **V2.2 原生界面**：环境检测、阶段进度、日志摘要、停止和失败页面均由 Avalonia 原生 UI 呈现，不创建业务 WebView。
- **V2.3 成功提交**：只有客户端文件就位、DSH 启动、Web UI 身份验证通过和自启动注册成功后，安装器才报告成功。
- **V2.4 用户停止**：任一未提交阶段点击停止，受管进程树退出，客户端文件、私有缓存、系统注册和中间目录完成回滚。
- **V2.5 失败回滚**：模拟下载失败、进程异常退出、端口竞态、健康检查超时和自启动注册失败，均不留下可运行的半安装客户端。
- **V2.6 日志可用**：失败结果保持可见并允许打开日志位置或复制诊断信息；日志不含 API Key、令牌和完整敏感环境变量。

## 3. npx 与数据隔离

- **V3.1 命令约束**：客户端通过未锁版本的 `npx @deepseek-ai/dsh web` 供应和启动 DSH，不执行 `npm install` 或全局安装。
- **V3.2 缓存隔离**：npx 下载只写入安装清单记录的私有 npm cache，不写入或删除用户共享 npm cache。
- **V3.3 DSH_HOME 隔离**：DSH profiles、插件、设置、凭据和会话均落入客户端私有 `DSH_HOME`。
- **V3.4 启动目录**：DSH 从客户端空白启动目录运行，不把安装目录或安装器当前目录作为默认用户工作区。
- **V3.5 版本变化**：缓存清理或 registry 版本变化后，客户端仍按相同未锁版本命令启动，不显示更新检测或升级 UI。

## 4. DSH 生命周期

- **V4.1 就绪判定**：仅有监听端口但返回非 DSH 内容时不得判定成功；DSH 页面身份验证通过后才显示 WebView。
- **V4.2 端口冲突**：3080 或持久化端口被未知进程占用时选择新端口，不接管、不终止未知进程。
- **V4.3 精确停止**：托盘退出只终止客户端拥有的 npx/Node/DSH 进程树，其他 Node 进程持续运行。
- **V4.4 优雅退出**：正常退出先触发 DSH 清理并等待限定时间；超时后只强制停止受管进程组。
- **V4.5 异常退出**：DSH 崩溃后客户端显示故障和日志入口，不发生无限快速重启。
- **V4.6 单实例**：重复启动不创建第二个 DSH，既有实例的主窗口被激活。
- **V4.7 只读诊断**：安装器、故障页面和 `--doctor` 对同一环境给出一致结果，诊断默认不修改系统或产品数据。
- **V4.8 有限修复**：启动失败最多普通重试一次；仅在确认私有缓存异常后清理私有 npx cache 并再试一次，不删除 `DSH_HOME`。

## 5. 窗口、WebView 与托盘

- **V5.1 标准窗口**：主窗口使用操作系统原生标题栏、拖动、最小化、最大化和关闭行为，不绘制自定义标题栏。
- **V5.2 WebView 范围**：安装和启动阶段不创建 WebView；DSH 就绪后直接呈现其 Web UI。
- **V5.3 无导航改写**：客户端不取消、重定向或转交 WebView 导航，也不注入宿主脚本桥接。
- **V5.4 业务交互**：内嵌 DSH Web UI 能完成工作区选择、普通输入和一轮流式响应。
- **V5.5 数据隔离**：Windows WebView2 使用客户端私有用户数据目录；macOS WKWebView 使用产品独立数据存储。
- **V5.6 Avalonia 托盘**：托盘由 Avalonia `TrayIcon` 创建；Windows 和 macOS 均可从菜单打开主窗口并退出。
- **V5.7 关闭行为**：安装完成后关闭主窗口仅隐藏窗口，DSH 与托盘继续运行；安装过程中关闭会进入停止与回滚确认。

## 6. 自启动

- **V6.1 默认注册**：全新成功安装后，操作系统登录项中出现本产品，命令使用后台启动参数。
- **V6.2 后台体验**：登录启动时客户端和 DSH 正常运行，托盘可用，主窗口不主动弹出。
- **V6.3 尊重系统设置**：用户在操作系统中禁用后，普通启动和覆盖安装不会擅自重新启用。
- **V6.4 卸载注销**：卸载后本产品登录项消失，其他登录项不变。

## 7. 干净卸载

- **V7.1 运行中卸载**：卸载器能够协调正在运行的客户端，先销毁 WebView、停止 DSH，再删除文件。
- **V7.2 精确删除**：客户端安装目录、状态、日志、私有 npm cache、`DSH_HOME`、启动目录和 WebView 数据全部删除。
- **V7.3 工作区保留**：多个外部工作区及其中由 DSH 创建或修改的文件均保持不变。
- **V7.4 系统环境保留**：系统 Node.js、用户 npm 配置、共享 npm cache 和其他 Node 进程保持不变。
- **V7.5 无锁残留**：Windows WebView2 和应用文件无锁定残留；macOS app bundle、Application Support、Caches 和产品 WebKit 数据完成清理。
- **V7.6 幂等恢复**：卸载中断后再次运行卸载器可继续清理，不扩大删除范围。

## 8. 平台发布

- **V8.1 Windows AOT**：`win-x64` 和 `win-arm64` Native AOT 发布成功；真实产物完成启动、安装事务、托盘、WebView 和卸载验证。
- **V8.2 macOS AOT**：`osx-x64` 和 `osx-arm64` Native AOT 发布成功；签名、公证后的真实产物完成相同验证。
- **V8.3 无 .NET 前置**：在未安装 .NET Runtime 的测试系统上，正式安装器、客户端和卸载器均正常运行。
- **V8.4 非 AOT 安装**：非 AOT、self-contained 产物无需系统 .NET，完成与 AOT 产物相同的核心安装和运行测试。
- **V8.5 源码构建**：安装 .NET SDK 后可执行普通构建、运行和测试，且不要求 Native AOT 才能进入开发循环。
- **V8.6 非便携准入**：正式验收以平台安装器为入口；直接运行开发构建不代表安装与卸载验收通过。
- **V8.7 GitHub Release**：正式产物只发布到 GitHub Releases，版本文件不可变，并同时提供 SHA-256、前置条件和签名/公证信息。
- **V8.8 无商店渠道**：项目不生成 Microsoft Store、WinGet 或客户端更新渠道所需的包、清单和运行逻辑。

## 9. 测试策略

- 纯状态机、路径所有权、端口选择、日志脱敏和补偿操作必须有自动化单元测试。
- npx 进程、HTTP 健康检查和失败回滚使用可控替身完成自动化集成测试。
- 安装器、托盘、自启动、WebView、系统退出和卸载必须在真实 Windows 与 macOS 环境进行人在环验收。
- CI 必须在 Windows 与 macOS 对各目标 RID 执行 Native AOT 发布；普通 `dotnet build` 成功不能替代该门禁。
- `Avalonia.Controls.WebView` 及每个新增第三方依赖都必须由真实 AOT 产物验证，不得仅凭包声明判定兼容。
- 破坏性测试只能操作测试专属产品目录和测试工作区，禁止以共享 Node/npm 数据作为清理目标。
