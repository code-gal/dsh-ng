# 产品需求定义 (PRD)

## 1. 定位
**dsh-ng-desktop** 是 DeepSeek Harness (dsh) 的第三方开源轻量桌面客户端（未来作为大 DIY 仓库的基础层）。它不仅守护和代理 dsh，还提供一键无痕分发的能力。

## 2. 核心功能特性

### 2.1 托盘守护与后台挂载
*   无窗口启动（潜行模式）：代理接管 dsh 服务端进程。
*   通过系统默认浏览器快速打开 Web UI（未来可平滑演化为内嵌 WebView 或 原生 GUI）。
*   对目标地址的代理抽象：系统默认优先寻找 `http://localhost:{port}`，但逻辑层需留出对外部远端 URL 支持的口子（BFF Proxy 概念）。

### 2.2 环境管理与防污染
*   启动时检测全局 Node.js 环境（无 Node 则拦截报错）。
*   **私有域安装**：利用全局 npm 但锁定安装在 `%LocalAppData%/dsh-ng-desktop` 数据目录下，绝对不污染系统全局的包注册表。
*   **可见的安装与更新**：任何安装/更新都必须有即时可见反馈（对话框或托盘气泡），禁止“点了菜单却毫无反应”。
*   **首次启动**：若尚未安装 DSH，弹出确认框后由用户选择是否立即安装；拒绝后托盘仍可驻留，菜单提供再次安装入口。
*   **打开面板**：仅在 DSH 已经安装后出现；未安装时不得提供该入口，也不得在打开面板时偷偷安装。
*   **检测更新 ≠ 自动更新**：已安装后可在启动时或菜单中检测 npm 上是否有新版本，只提示、不自动升级；用户手动选择“更新”后才执行。
*   **安装过程可见**：首次安装必须显示阶段进度、实时日志和失败原因；安装完成后自动启动 DSH 并打开浏览器。
*   **窗口化方向**：桌面壳将演进为“托盘 + 简单窗口”模式；首个窗口聚焦安装向导与状态展示。
*   **远程连接预留**：首启向导保留“连接远程 dsh”的扩展口子，但当前实现仅覆盖本地安装链路。

### 2.3 端口智适应
*   寻找可用端口（检测占用则自增）。
*   一旦探明立刻固化到 JSON 并重复使用，避免下次启动地址变动导致用户的浏览器历史书签失效。

### 2.4 完全洁净卸载机制（核心卖点）
桌面应用的一大痛点是垃圾残留。点击彻底卸载时必须执行：
1. 强制杀死正在下辖的 Node / dsh 进程。
2. 剥离已注册的系统自启动项。
3. 清除 %LocalAppData% 下的特属文件夹（连带整个 node_modules 环境）。
4. 在 Temp 下产生自运行毁尸灭迹脚本 (`.bat`) 脱离进程依赖从而删除托盘 `.exe` 本身。
