# 产品需求定义

## 1. 产品定位

**dsh-ng-desktop** 是 DeepSeek Harness（DSH）的第三方跨平台桌面客户端，主要面向 Windows，同时支持 macOS。客户端负责 DSH 的安装、启动、停止、托盘驻留、自启动注册和干净卸载；DSH 的业务界面直接使用其原生 Web UI。

客户端不修改 DSH Web UI，不承担 DSH 或客户端的版本比较、更新提示和兼容性管理。

## 2. 发行与安装

### 2.1 正式发行形态

- Windows 与 macOS 分别构建原生安装器和应用产物，共享安装流程与桌面运行逻辑。
- Windows 是首要交付平台；macOS 使用同一产品状态机和平台适配接口实现。
- 正式安装包只通过项目 GitHub Releases 发布，由用户手动下载和安装；不规划 Microsoft Store、WinGet 或客户端内更新渠道。
- GitHub Release 必须提供版本化产物、校验值和必要的签名信息，已发布的同名版本文件不得替换。
- 正式发行不以“解压即用”或单个便携程序替代安装器，因为便携模式无法完整保证事务回滚、系统卸载、自启动注册和残留清理。

### 2.2 构建形态

- 正式发布的安装器、桌面客户端及全部 .NET 辅助程序默认使用 Native AOT、自包含构建，目标机器无需安装 .NET。
- Native AOT 是代码设计和正式发布的硬性准入条件，不得先编写依赖 JIT、动态代码生成或未声明反射的实现，再以非 AOT 产物绕过。
- 同一安装流程支持非 AOT、自包含构建，供兼容性诊断和特殊环境使用；该构建同样无需目标机器预装 .NET。
- 支持开发者安装 .NET SDK 后直接从源码执行普通构建和运行。
- Windows 与 macOS 按操作系统和 CPU 架构分别构建，不要求单一二进制跨平台运行。

### 2.3 安装事务

- DSH 是客户端安装事务的一部分，不得等客户端安装完成后再以“首次启动任务”补装。
- Windows 安装器使用中文 Avalonia 原生安装引导窗口展示环境检测、阶段进度、日志摘要、失败原因和停止操作，并可打开安装位置；目标尚未创建时只打开其现有父目录，不为查看位置创建安装目录。
- 安装成功必须同时满足：客户端文件就位、DSH 进程成功启动、本地 Web UI 健康检查通过、自启动完成注册。
- 任一阶段失败或用户停止时，安装事务失败；安装器必须停止受管进程、清理本次创建的数据、取消系统注册并回滚客户端文件。
- 失败信息在回滚前保持可见，允许用户复制或打开安装日志。
- 若检测到旧产品数据，安装器必须先要求用户选择：覆盖安装仅替换客户端文件并保留 DSH 数据；全新安装在明确确认后清理全部产品受管路径再安装。当前安装日志在安装器退出前保留供诊断，不因全新安装被删除。有效安装清单证明该范围属于产品，仍可供用户选择两种方式；无清单的中断数据也可选择两种方式。无法验证的清单状态只允许用户明确选择全新安装，不得自动清理或扩大删除范围。
- 全新安装清理产品私有目录时，必须能处理依赖缓存留下的只读项，不跟随符号链接或其他重解析点；清理仍失败时必须保留未删除内容，并明确指出受管根目录和失败项，而不是只显示无上下文的子目录名称。

### 2.4 Node.js 前置条件

- 客户端不携带、不自动安装、不卸载私有 Node.js。
- 安装器必须先检测系统已有的 `node` 与 `npx`，并验证其能够启动 DSH。
- 首次 `npx` 供应 DSH 时，安装器必须持续等待至 DSH 就绪、受管进程退出或用户停止；不得以普通启动的短超时或固定安装时限中止首次安装。
- 长时间供应期间，安装器必须以单一主状态、单一已等待时长和有意义的摘要进展展示过程；在长时间无新输出时提示仍在等待且可随时停止，不将其直接报告为安装失败。
- Node.js 缺失或不兼容时，安装立即停止并提供明确的安装指引；用户修复环境后重新运行安装器。
- 卸载不得删除用户或其他软件安装的 Node.js、npm 配置和共享 npm 缓存。

## 3. DSH 管理

### 3.1 安装与启动命令

- DSH 必须通过未锁版本的 `npx @deepseek-ai/dsh web` 安装并运行，禁止改用 `npm install`、全局 npm 安装或客户端自维护包更新。
- 客户端允许 npx 在后续启动时取得变化后的 DSH 版本，不比较版本、不提示可用更新、不回滚 DSH 更新；启动过程可如实显示“正在检查 DSH 更新”，并仅在 npx 输出表明正在下载、解压或安装包时显示“正在更新 DSH”，不显示具体版本或伪造百分比。
- 启动状态必须明确区分启动失败、DSH 运行中异常退出、检查 DSH 更新时的网络错误和更新 DSH 失败；主窗口与后台托盘显示同一错误类别及简短说明，完整 npx 输出只写入运行日志。
- npx 执行缓存必须定向到客户端私有目录，避免污染或依赖用户的共享 npm 缓存。
- `DSH_HOME` 必须定向到客户端私有目录，使 DSH profile、配置、凭据、插件和会话具有明确的卸载归属。
- DSH 从客户端专属的空白启动目录运行，不把客户端安装目录或任意用户目录隐式设为工作区。

### 3.2 进程与端口

- 客户端只管理自己创建的 npx、Node 和 DSH 进程树，禁止按进程名称批量终止系统中的 Node 进程。
- DSH 仅监听 loopback。默认优先使用 3080；端口被未知进程占用时选择并持久化其他可用端口。
- 安装和正常启动均以 DSH Web UI 健康检查通过作为就绪条件，不以端口可连接或进程仍存活作为唯一依据。
- 正常停止先请求 DSH 优雅退出，超时后再强制终止客户端拥有的进程树。
- DSH 异常退出时，客户端显示故障状态和日志入口，不进行无上限自动重启。
- 客户端提供共享的环境诊断能力，供安装器、故障页面和可选命令行诊断复用；诊断默认只读。
- 自动修复仅限安全操作：重新定位 Node/npx、重试启动，以及确认私有 npx 缓存损坏后清理该缓存并重试一次。
- 自动修复不得删除 `DSH_HOME`、修改系统 Node/npm 环境或无限循环重试。

### 3.3 本地测试工程

- 单元测试工程固定放在 `dsh-ng-desktop/LocalTests/`，仅供本机开发与验收使用，不进入 Git 协同。
- 本地测试工程可以引用桌面项目，并只可创建其自身临时目录及测试专属产品数据根目录；不得把测试产物写入安装目录、用户共享 npm 缓存、真实 `DSH_HOME` 或用户工作区。
- 正式代码必须保持可自动化测试的窄接口边界；本地测试工程的存在、缺失或内容均不得影响应用构建、打包、安装器或正式发行物。

## 4. 桌面体验

### 4.1 原生窗口与 WebView

- 客户端使用 Avalonia 标准桌面生命周期和操作系统原生标题栏。
- 环境检测、安装进度、回滚和运行故障页面全部使用客户端原生 Avalonia UI。
- 只有 DSH Web UI 使用内嵌 `NativeWebView`；在 DSH 健康检查通过前不得创建或显示业务 WebView。
- WebView 直接呈现 DSH Web UI，不添加客户端导航限制，不拦截外部链接，不提供网页到宿主的脚本桥接。
- Windows 使用客户端私有 WebView2 用户数据目录；macOS 使用独立的 WKWebView 数据存储标识。相关缓存随客户端卸载。
- 客户端记录安装与运行日志，并提供可理解的错误摘要和日志位置。
- 安装引导的日志面板展示经整理的摘要而非完整依赖下载输出，支持自动换行、紧凑行距、手动滚动、文本选择和复制；用户查看历史内容或选择文本时，后续日志不得强制跳回末尾或清除选择。

### 4.2 托盘与窗口生命周期

- 托盘统一使用 Avalonia `TrayIcon` 和原生菜单能力，不自行实现 Win32 托盘。
- Windows 左键托盘图标打开主窗口，右键菜单至少提供“打开 DSH”和“退出”。
- macOS 遵循菜单栏图标的原生交互，在菜单中提供“打开 DSH”和“退出”，不强求复制 Windows 左右键行为。
- 后台自启动时不显示主窗口；托盘提示文本应反映 DSH 的启动阶段、就绪或失败。用户从托盘打开主窗口后，看到与前台启动一致的原生状态。
- 安装完成后的窗口关闭操作隐藏主窗口并保留托盘和 DSH；安装事务中的关闭操作等同于停止并回滚前的确认。
- 托盘“退出”必须先停止 DSH，再退出客户端。
- 客户端只允许运行一个实例；重复启动时激活既有实例的主窗口。

## 5. 开机自启动

- 安装事务成功时默认注册当前用户开机自启动，自启动参数以后台模式启动客户端和 DSH，不主动弹出主窗口。
- 客户端内不提供自启动开关；用户通过操作系统设置启用或禁用。
- 客户端启动和升级不得重新启用已被用户在操作系统中禁用的自启动项。
- 卸载必须注销本产品的自启动项，不影响其他登录项。

## 6. 干净卸载

卸载必须：

1. 通知运行中的客户端进入卸载状态并停止接受新操作。
2. 销毁 WebView，优雅停止 DSH，必要时强制终止客户端拥有的进程树。
3. 注销 Windows 或 macOS 自启动项及产品安装注册。
4. 删除客户端安装目录、状态、日志、私有 npx 缓存、`DSH_HOME`、WebView 数据和安装中间目录。
5. 删除客户端安装的 DSH profile、插件、会话、配置和凭据。
6. 保留用户选择的所有工作区目录及其中的全部文件，不尝试回滚 DSH 曾对工作区执行的修改。
7. 保留系统 Node.js、用户 npm 配置、共享 npm 缓存和非本客户端创建的进程。

Windows 通过系统卸载入口执行完整清理；macOS 正式发行物必须提供可执行完整清理的卸载入口，不能把“将 `.app` 拖入废纸篓”视为满足干净卸载。

## 7. 非目标

- 客户端和 DSH 的版本比较、更新提示、版本固定和兼容性治理。
- 修改、复制或替代 DSH Web UI。
- 远程 DSH 连接。
- 客户端内的自启动开关。
- Linux 正式发行。
- 删除或恢复用户工作区内容。
- Microsoft Store、WinGet 和其他应用商店发行。
- 客户端内下载或安装客户端更新。
