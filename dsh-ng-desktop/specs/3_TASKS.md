# 开发任务状态机

## M0：重构基线

- [x] **M0.1 方案定稿**：重写产品需求、架构和验收规范，确立安装器事务、npx 私有缓存、原生安装 UI、WebView 业务 UI、Avalonia 托盘和干净卸载边界。
- [x] **M0.2 代码归零**：移除旧 Win32 托盘、`npm install` 调度、更新逻辑、旧安装向导和 WebView 实验窗口，保留可构建的 Avalonia 工程骨架与品牌资源。

## M1：共享基础与平台边界

- [ ] **M1.1 应用状态机**：实现显式的安装、启动、就绪、停止、回滚和故障状态。
- [ ] **M1.2 数据所有权**：实现 `AppPaths` 与 `InstallManifest`，覆盖 Windows 和 macOS 的全部受管路径。
- [ ] **M1.3 日志系统**：实现安装/运行日志、轮转、脱敏、打开位置和复制诊断信息。
- [ ] **M1.4 单实例与 IPC**：重复启动时激活已有主窗口。
- [ ] **M1.5 平台服务接口**：隔离进程组、自启动、安装注册和卸载能力。

## M2：DSH 供应与监督

- [ ] **M2.1 Node 环境检测**：定位并验证系统 `node` 与 `npx`，缺失时给出原生错误和修复指引。
- [ ] **M2.2 私有运行环境**：配置独立 npm cache、`DSH_HOME` 和安全启动目录。
- [ ] **M2.3 npx 启动**：使用未锁版本的 `npx @deepseek-ai/dsh web` 后台供应并运行 DSH。
- [ ] **M2.4 端口与健康检查**：实现端口复用、冲突迁移、竞态重试和 DSH 身份验证。
- [ ] **M2.5 进程所有权**：实现 Windows Job Object、macOS process group、优雅停止和超时强制停止。
- [ ] **M2.6 异常恢复**：DSH 异常退出时进入故障状态，提供有限重试和日志入口。

## M3：安装器事务

- [ ] **M3.1 原生安装引导**：实现 Avalonia 环境检测、阶段进度、日志摘要、停止和失败页面。
- [ ] **M3.2 事务提交与补偿**：DSH 健康检查通过后才提交；取消或失败时完整回滚。
- [ ] **M3.3 Windows 安装器**：实现当前用户安装、系统卸载注册和失败回滚。
- [ ] **M3.4 macOS 安装器**：实现双架构签名、公证、安装事务和完整卸载入口。

## M4：桌面运行体验

- [ ] **M4.1 标准主窗口**：使用原生标题栏承载安装/故障原生视图和 DSH WebView。
- [ ] **M4.2 WebView 数据隔离**：实现 Windows WebView2 私有目录与 macOS WKWebView 独立数据存储。
- [ ] **M4.3 Avalonia 托盘**：实现平台原生菜单、“打开 DSH”和“退出”。
- [ ] **M4.4 窗口生命周期**：正常关闭隐藏到托盘；安装中关闭进入停止与回滚确认。
- [ ] **M4.5 后台自启**：安装成功默认注册，后台启动不弹窗，并尊重操作系统禁用状态。

## M5：干净卸载与发布

- [ ] **M5.1 卸载协作**：运行中应用接收卸载请求，销毁 WebView并停止 DSH。
- [ ] **M5.2 精确清理**：删除安装清单内的客户端、npx、DSH_HOME、日志和 WebView 数据，保留工作区和系统 Node。
- [ ] **M5.3 Windows 验收**：完成安装成功、失败回滚、自启、托盘、退出、卸载和残留检查。
- [ ] **M5.4 macOS 验收**：完成 Intel/Apple Silicon 安装、自启、菜单栏、退出、卸载和残留检查。
- [ ] **M5.5 发布构建**：生成签名的各平台正式安装产物和校验信息。
